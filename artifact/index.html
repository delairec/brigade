One request in, one merge out.

brigade is a CLI, a timer and a local dashboard that turn a request into a wave of tasks, run the tasks as agent runs in worktrees, verify every pull request, merge the compliant ones into an integration branch, and leave the user one report and one merge. The CLI does everything mechanical; the agents only judge.

In one minute

  • What it isA kitchen brigade for the machine: the user is the chef, the cooks are the roles, the user's own where an instructions corpus is configured, brigade's built-in roles otherwise; brigade is the expediter who orders, times and checks every plate. Python standard library shipped as one file, a scheduler of the machine (systemd timer, cron or a loop), a loopback web page; the AI client sits behind an adapter, Claude Code first; awawa is read as it is.
  • What it doesbrigade wave new <project> "…" → a planner cuts the request into tasks on an integration branch → the tick launches runs in dependency order, four at a time → each PR goes through the pass (deterministic preflight, then one verifier run) → compliant PRs merge into integration → a report, a dependency graph and a manual-test table are written → the user merges integration into main. A study does the same for work that is not code: collectors assemble the evidence, one run judges, the answer lands where the study says. A recipe lets the user declare a kind of work of their own from the same steps.
  • Where it savesMeasured today: a build run makes its first edit after 23 steps and 134 000 tokens of discovery; 146 steps a week went to re-reading oversized outputs; rebases took 53 steps on a model. The CLI hands each run one pre-computed package and does the rest itself; the estimate is 200 to 270 agent steps saved per wave of 15 tasks, to be confirmed by the ledger.
  • Outer loopReview threads, failing checks, local notes, gardening scans and corrections mined from transcripts become signals in a buffer; triage groups them into patterns; one ratification turns a pattern into a wave or a constraint (rule, guard, lint, script), merged like any other work and listed in the report.
  • InterfaceA web dashboard served locally, with a selector to browse any branch or worktree's corpus without checking it out; the IntelliJ plugin stays for in-IDE work, awawa-web stays as the structural editor of the brigade's own corpus.
  • SafetyEverything lands on branches; the forge account merges into integration/* only; an unattended run never assumes; a stuck wave parks with a question. The user's one gate is the merge into main.

What the user settled

  • AutonomyBeyond pull requests: planning, building, verifying, merging into integration and reporting run without the user. Changes to the instructions corpus are allowed if the report lists them with their reason.
  • StorageHybrid: awawa corpora for durable facts, an append-only JSONL ledger for events.
  • IntakeAll four sources, phased: review threads and CI failures first, then notes, gardening scans, transcript corrections.
  • ExecutionLocal only: a scheduler of the machine runs the tick, runs are unattended subprocesses brigade owns.
  • BudgetNo cost cap (subscription); the plan pauses and resumes a wave when the rate-limit window closes; statistics come from the result data the client adapter normalises. Waves of 10 to 20 pull requests.
  • ReviewA verifier agent checks every PR; the user reviews at the merge into main, from the report and the manual-test table; sampling stays a suggestion.
  • First principleThe CLI does everything mechanical; agents only judge. Every lifecycle step is marked accordingly, agents never rediscover state through git, gh or file reads, and the POC starts with the deterministic commands.
  • PortabilityAgnostic of the AI client: five adapter operations with a fallback each, the supported clients tabled in the README; roles are slots bound to role files, the user's roles by default, custom ones in a directory; installs on any Linux with Python 3.11, git, awawa and one adapted client; systemd, gh, the machine account and the instructions corpus optional.
  • StudiesReports, collections, audits and research are studies: deterministic collectors, then at most one judging run; scans are studies without judgment.
  • RecipesA kind of work is a recipe: ordered process-shaped steps in a file, run by the tick; an order is one instance; wave stays native, study is the first built-in recipe; plugins on PATH add clients, collectors, checks and outputs.

The POC, task by task

Fifty-three tasks in nine milestones, deterministic commands first. Statuses are mirrored from the corpus by brigade board sync: the corpus is their one home, and a status changed here binds nothing.

Connecting to the board…

For an agent: each document lives at tasks/<id> with the fields status, notes, updated_at; the field status holds the corpus STATUS verbatim, is changed in docs/tasks.awawa, never here, and is written only by brigade board sync. The "copy brief" button on a task copies its title, acceptance line, dependencies and role, ready to paste into a launch.
